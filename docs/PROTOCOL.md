# Prospective experiment protocol

Written before the main campaign; pilot output is excluded. This is a local, timestamped protocol, not an externally registered study.

## Scope and research questions

Single-replica Redis 7.4.2 and NATS JetStream 2.10.24; all performance experiments, fault injections and harness validation execute only in `kubectl --context homelab`, namespace `msgrel-20260923`. Local computation is limited to artifact authoring, descriptive/statistical analysis and PDF compilation. The study does not claim universal performance rankings, formal verification of vendor implementations, exactly-once business effects, host-power-loss survival, cluster failover, WAN behavior, or population-wide statistical generalization.

RQ1 measures first successful redelivery after SIGKILL of an actual consumer child process with one delivered, unacknowledged message. A Linux monotonic clock on the driver node provides all timing endpoints. Configured expiration is 250 or 1000 ms; kill ages are approximately 10% or 75% of expiration. Redis reclaims via XAUTOCLAIM, COUNT 1, from 0-0, at 10 or 100 ms intervals with randomized initial phase. NATS uses explicit acknowledgment, no backoff, and a pending pull on the same durable. Ten repetitions per cell. A no-reclaim Redis control demonstrates that new-message reads do not reclaim pending work. Recovery is conditional on retained data and available server/consumer; censoring and faults must be preserved, not silently dropped.

RQ2 compares 1, 2, 4, 8, and 16 logical consumers, each with its own TCP connection, sharing one Redis consumer group or one NATS durable pull consumer. COUNT/batch = 1, no synthetic application work, acknowledgment completion awaited per message. Ten randomized complete blocks contain all 30 engine/durability/concurrency conditions. Each trial has an excluded 256-message warm-up followed by 16384 messages of 512 bytes. A backlog-drain phase isolates consumption from producer speed. Throughput counts unique acknowledged IDs divided by complete drain time; delivery and acknowledgment timestamps and worker counts are retained. The observed workload includes client-library, network, pull, and acknowledgment costs and is not a universal server capacity measurement.

RQ3 compares volatile storage, periodic synchronization, and synchronization requested on each operation. Redis: save disabled; appendonly no, appendfsync everysec, or appendfsync always. NATS: memory stream, file stream with explicit sync_interval 1s, or file stream with sync_interval always. Replication factor one. Configurations are conceptually aligned but are not assumed to have identical implementation guarantees. Redis AOF automatic rewrites disabled to isolate the bounded steady-state path. Disk storage is a disk-backed emptyDir on the same server node, surviving container restart but not pod deletion. Publication uses 16 concurrent publishers with one outstanding confirmation per publisher. The primary independent RQ3 series runs each profile for 5 seconds of confirmed publication in ten randomized complete blocks, spanning several nominal synchronization intervals. The fixed-backlog prefill publication data are supporting evidence only. A 1-publisher sensitivity series uses ten blocks and 1024 messages. Redis XADD replies and JetStream PubAck are measured as their respective documented acceptance contracts. Consumer acknowledgments use XACK replies and JetStream AckSync.

## Analysis fixed before the main campaign

Randomization seed 20260923. Experimental unit is one trial, not a message. Report mean throughput with 95% bootstrap confidence intervals across the ten trial blocks, and mean within-trial p50/p95/p99 latency with intervals across runs. Comparisons use paired block bootstrap ratios (10,000 resamples, fixed seed); no per-message significance tests or unplanned significance-based stopping. A family of exploratory comparisons is not labeled confirmatory hypothesis testing. Failure trials report all samples, medians, quantiles, and censor counts. Zero observed losses is a finite observation, not a proof of zero risk. Raw per-message timings, JSONL summaries, exact configs, image digests, source checksums, environment receipts, exclusions and deviations are retained.

The driver is a closed-loop finite workload: publication latency is request-to-confirmation, and drain latency is measured from the common drain start. It must not be labeled a fixed-arrival-rate SLA latency benchmark. Ordered publication IDs are application IDs, not a claim about global ordering across producers.

## Validation and controls

Each trial requires all application IDs unique and acknowledged, no unexpected errors, no pending acknowledgments, and exact expected storage counts. Fault injection confirms SIGKILL exit and identity of the recovered message. Pilot conditions validate the harness and do not enter inferential results. Run telemetry records CPU usage and cgroup throttling of the driver; record server telemetry and environment before/after campaign. Short trials, shared hardware, timer quantization, protocol differences, warm caches and one client implementation are explicit limitations. Preserve failed trials. Any repair is versioned in the deviation log and requires rerunning affected main conditions.
